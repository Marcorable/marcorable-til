# 2026-11-02

## 오늘의 기록

Notion의 레거시 자료를 Record, Todo, Calendar 중심의 최신 구조로 옮기고, 날짜별 기록과 주제별 지식을 함께 탐색할 수 있도록 연결했다. 원본과 대상 URL의 매핑을 유지하고 회사 관련 자료는 기존 위치에 남겨, 대규모 이전에서도 검증 가능성과 복구 가능성을 우선했다.

ReciteScripts에서는 저장·목록 흐름과 낭독 세션 설정을 차례로 병합한 뒤 실제 낭독 화면 구현까지 진행했다. CCRecorder의 기존 변경도 병합하고 Android 네이티브 버전의 첫 구현 범위를 정했으며, 반복되는 개발 규칙과 에이전트 협업 방식은 별도의 팩과 운영 문서로 정리했다.

## 배운 점

### 대규모 지식 이전은 분류보다 추적 가능성이 먼저다

- 원본 URL과 대상 URL을 함께 남기면 누락·중복을 확인하고 문제가 생겼을 때 이전 상태를 복원할 수 있다.
- 완료 이력과 빈 학습 페이지를 모두 활성 Todo로 옮기면 매일의 작업 화면이 과거 항목에 묻힌다. Active, Someday, Done처럼 현재 의미를 드러내는 상태가 필요하다.
- 원본 제거는 일괄 삭제보다 대상 검증 후 휴지통 이동처럼 되돌릴 수 있는 단계로 진행하는 편이 안전하다.

### Daily Log와 주제별 Record는 서로 다른 탐색 축을 제공한다

- Daily Log는 그날의 맥락과 진행 순서를 보존하고, Record는 나중에 주제 중심으로 다시 찾기 좋은 지식 단위가 된다.
- 한 날짜의 TIL을 여러 Record로 분리하더라도 날짜별 Daily Log에서 연결하면 시간 순서와 주제 구조를 동시에 유지할 수 있다.
- 제목만 복사하지 않고 본문에서 핵심 내용을 추려야 Record가 다시 사용할 수 있는 지식이 된다.

### 자동 검증과 실기기 검증은 완료 기준을 나눠 가진다

- 테스트와 양 플랫폼 빌드는 구현의 회귀와 컴파일 경계를 빠르게 확인하지만, 음성 입력과 접근성 동작의 실제 품질까지 보장하지는 않는다.
- STT, VoiceOver/TalkBack, Reduce Motion처럼 환경과 사용자 설정에 의존하는 기능은 실기기 검증을 별도 완료 조건으로 남겨야 한다.

### 에이전트 협업은 역할보다 권한 경계가 구체적이어야 한다

- Mission 안에서 구현과 검증을 자율화하더라도 push, PR, 외부 게시와 파괴적 정리는 별도의 승인 지점으로 구분할 수 있다.
- 제품 결정과 작업 행정을 나누면 에이전트가 상태와 증거를 관리하면서도 우선순위나 공개 약속을 임의로 바꾸지 않게 된다.
