# 2026-11-21

## 오늘의 기록

ReciteScripts에서 스크린샷 촬영 중 발생하는 일시적인 앱 상태 변화를 실제 백그라운드 전환이나 종료와 구분하고, 낭독 세션이 잘못 정리되는 문제를 수정했다. 회귀 테스트와 양 플랫폼 빌드, CI까지 통과시켜 구현 결과를 검증 가능한 상태로 만들었다. 한편 국내 외주 활동은 취업 준비를 방해하지 않는 작은 실험으로 정의하고, 사용할 채널과 시간·실행 목표를 구체화했다.

## 작업 기록

### 완료

- 스크린샷 촬영으로 앱이 잠시 비활성화될 때는 낭독 세션을 유지하도록 ReciteScripts의 생명주기 처리를 수정했다.
- 실제 백그라운드 전환과 화면 종료에서는 기존처럼 세션이 정리되는지 확인하는 회귀 테스트 2개를 추가했다.
- 전체 140개 테스트, Android·iOS 빌드와 GitHub CI를 통과하고 수정 사항을 PR #128로 정리했다.
- 국내 외주 채널 조사를 마치고 초기 운영 채널을 위시켓과 크몽으로 좁혔다.
- 외주 활동을 주 2시간으로 제한하고, 첫 4주 목표를 위시켓 맞춤 지원 6건과 크몽 서비스 2개 공개로 정했다.

### 진행 중

- ReciteScripts PR #128과 기존 PR #122·#124는 최종 리뷰와 병합을 기다리고 있다.
- 직접 수주를 시작하기 전에 계약·견적 템플릿을 준비해야 한다.

### 다음에 할 일

- ReciteScripts의 대기 중인 PR을 최종 검토하고 병합 여부를 결정한다.
- 외주 채널별 프로필과 제안 내용을 준비하고, 정한 시간 상한 안에서 4주 실험을 시작한다.
- 직접 수주에 사용할 계약·견적 템플릿을 완성한다.

## 배운 점

### 모바일 생명주기는 상태 이름보다 전환의 의미를 검증해야 한다

- 앱의 일시적인 `inactive` 상태가 항상 작업 중단을 뜻하지는 않는다. 스크린샷 촬영처럼 사용자 작업을 계속 유지해야 하는 시스템 이벤트와 실제 백그라운드 전환을 구분해야 한다.
- 수정의 완료 조건은 문제 경로만 고치는 것이 아니라, 유지돼야 하는 상태와 정리돼야 하는 상태를 각각 회귀 테스트로 고정하는 것이다.
- 단위 테스트뿐 아니라 양 플랫폼 빌드와 CI까지 함께 확인해야 변경이 통합 가능한 상태라는 근거가 된다.

### 새로운 수익 활동은 범위와 중단 조건이 있는 실험으로 시작할 수 있다

- 여러 채널을 동시에 운영하기보다 초기 채널을 좁히고 일정 기간의 행동 목표를 정하면 결과를 비교하기 쉽다.
- 주간 시간 상한을 먼저 정하면 외주 탐색이 취업 준비라는 우선순위를 침범하는 것을 막을 수 있다.
- 직접 수주는 기회가 생긴 뒤 준비하는 것이 아니라 계약과 견적의 기준을 먼저 갖춘 뒤 시작해야 운영 위험을 줄일 수 있다.
