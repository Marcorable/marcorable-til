# 2026-11-10

## 오늘의 기록

ReciteScripts의 낭독 화면 접근성과 UI 회귀를 여러 PR로 나누어 검증하고 병합했다. 권한·설정 흐름, 작은 화면과 긴 제목, Accessibility XL, 48dp 터치 영역, 비활성 버튼의 형태 단서와 유리 표면 대비까지 테스트와 양 플랫폼 빌드로 확인했다.

출시 준비에서는 스토어 프로모션 스크린샷과 iOS 심사 문서를 교차 검토하고 Figma 디자인 파일과 디자인 시스템 정리를 진행했다. 개발 워크플로에는 CodeRabbit rate limit을 병합 차단 조건으로 삼지 않고 현재 head SHA의 Codex 리뷰와 필수 CI로 판단하는 기준을 추가했다.

## 배운 점

### 접근성 상태는 색상뿐 아니라 형태와 실제 크기로 검증한다

- 비활성 버튼이 색상만 달라지면 색각이나 대비 조건에 따라 상태를 구분하기 어렵다. 금지 표시처럼 형태 기반 단서를 더하면 색상에 의존하지 않고 상태를 전달할 수 있다.
- 버튼의 선언 크기가 충분해 보여도 상위 Navigation Bar의 제약으로 실제 터치 영역이 줄어들 수 있다. 플랫폼별 렌더링 결과와 실제 48dp 이상 영역을 테스트해야 한다.
- 큰 글자 크기, 작은 화면과 긴 제목을 함께 검증해야 접근성 수정이 다른 레이아웃 회귀를 만들지 않았는지 확인할 수 있다.

### 외부 리뷰 도구의 제한과 필수 품질 기준을 분리한다

- CodeRabbit의 rate limit은 코드 품질 결과가 아니라 외부 서비스의 실행 제한이다. 이를 무한 재시도하거나 병합 차단 조건으로 사용하면 작업 흐름이 불필요하게 멈춘다.
- 현재 PR head SHA를 대상으로 한 Codex 리뷰와 필수 CI가 완료됐는지 확인하고, 이전 SHA의 리뷰 결과는 최신 변경의 검증으로 인정하지 않는 기준이 필요하다.

## 기록에서 배운 점

### [Daily iOS / 1주 1일차](https://app.notion.com/p/414d5c4871bd8087bb48d9bd84acb80b)

- Generic은 컴파일 타임에 타입 제약과 구체 타입을 활용할 수 있지만 `Any`는 타입 정보가 지워져 런타임 캐스팅이 필요하다. 서로 다른 타입을 하나의 Generic 매개변수로 추론할 수 없다는 점도 함께 확인했다.
- `inout`은 단순한 참조 전달이 아니라 copy-in/copy-out 의미를 가진다. 함수 반환 뒤에도 살아남는 escaping 클로저에는 캡처할 수 없고, 같은 메모리에 겹치는 쓰기 접근은 exclusivity 규칙을 위반한다.
- class 인스턴스를 `let` 매개변수로 전달해도 재할당만 막을 뿐 참조 대상의 변경은 막지 못한다. 깊은 복사가 필요하면 `NSCopying` 같은 계약을 사용해 중첩 참조까지 직접 새 인스턴스로 만들어야 한다.
- 작고 복사 가능한 불변 데이터는 struct가 적합하고, tuple은 함수의 다중 반환이나 한 스코프 안에서 바로 분해되는 짧은 수명의 묶음에 적합하다.
- 강제 언래핑은 외부 입력이나 런타임 조건에서 크래시를 만들 수 있다. `nil`이 프로그래머 오류인 IBOutlet·번들 리소스처럼 제한된 경우에만 실패 이유를 명확히 남기고 사용해야 한다.
