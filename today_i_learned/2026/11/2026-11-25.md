# 2026-11-25

## 오늘의 기록

채용 포털 이력서와 프리랜서 서비스·프로필을 최신 근거에 맞춰 정리하고, 공개 가능한 사실과 아직 검증하지 않은 성과를 분리했다. 하네스 엔지니어링 포트폴리오와 학습 계획도 같은 원칙으로 다듬어 재사용할 증거와 보류할 수치를 구분했다. ReciteScripts에서는 런치스크린 수정과 진입 애니메이션을 별도 작업으로 나눴으며, 외부 이슈 생성은 승인 전 단계로 남겼다.

## 작업 기록

### 완료

- 잡코리아와 사람인의 경력·담당업무·경력기술서·자기소개서를 최신 문서 기준으로 갱신하고 기존 첨부와 공개 설정을 보존했다.
- 초기 외주 서비스 3종의 범위, 제외 조건, 산출물, 기간, 상담·견적 기준과 검수 조건을 정의하고 Linear MAR-70을 완료했다.
- 국문 프리랜서 프로필에서 큐마켓의 공개 범위를 확정하고, 베리모지는 서비스 종료로 현재 스토어 링크가 없는 과거 상용 앱 경험으로 정리했다.
- 하네스 엔지니어링 포트폴리오의 증거 인벤토리와 2페이지 사례 구조를 작성하고 검증되지 않은 수치를 분리했다.
- 에이전틱 엔지니어링 10일 학습 계획에 공식 자료, 테스트와 Eval, 실패 징후, 단일 에이전트 비교와 책임 점검을 배치했다.

### 진행 중

- ReciteScripts의 iOS 런치스크린 이미지 교체와 앱 진입 로고 선택 애니메이션은 별도 이슈 후보로 범위만 정리된 상태다.
- 하네스 포트폴리오의 기간·PR·이슈·테스트 수치는 원자료를 다시 계산하기 전까지 최종 성과로 사용하지 않는다.

### 다음에 할 일

- ReciteScripts의 두 이슈를 생성할지 승인한 뒤 런치스크린 수정부터 순서대로 진행한다.
- 하네스 포트폴리오 수치의 원 태그, GitHub 이력과 테스트 리포트를 재검증한다.
- 10일 학습 계획에 확정한 자료와 책임 점검 기준을 실제 일정표에 반영한다.

## 배운 점

### 외부에 공개할 문서는 사실과 현재 상태를 함께 써야 한다

- 회사명과 서비스명처럼 공개 범위가 확정된 정보는 일관되게 사용하되, 종료된 서비스에는 현재 링크가 없다는 상태를 명확히 밝혀야 한다.
- 라이브 링크가 없다는 이유로 과거 역할이나 성과를 보강해서는 안 된다. 내부 문서와 이력처럼 확인 가능한 근거만 남기는 편이 신뢰를 높인다.
- 포트폴리오 수치는 반복 인용됐더라도 원자료를 재계산하지 않았다면 서술 근거와 확정 성과를 분리해야 한다.

### 큰 계획은 비교 기준과 책임 점검까지 포함해야 실행 가능하다

- 학습 자료는 많이 모으기보다 공식성, 당일 실습과의 연결, 기존 자료와의 차이를 기준으로 선별할 수 있다.
- 구현자와 검토자를 나누는 효과는 단일 에이전트 기준선과 비교해야 판단할 수 있다.
- 매일 결과를 AI 없이 설명할 수 있는지 확인하면 위임과 이해, 최종 책임의 경계를 유지할 수 있다.

### [Explore structured concurrency in Swift](https://app.notion.com/p/40cd5c4871bd8112b5bce76c195d92f7)

- `async` 함수를 호출하는 것만으로 새 Task가 생기지는 않으며, `async let`은 수가 정해진 자식 작업을 구조화해 함께 관리한다.
- 취소는 작업 중단을 강제하는 명령이 아니라 상태 전달이므로 `Task.checkCancellation()`이나 `Task.isCancelled`로 협력해야 한다.
- Task Group은 동적으로 작업을 추가하고 결과를 안전하게 모으는 데 적합하며, 공유 가변 상태를 자식 Task에서 직접 수정하지 않아야 한다.

- 이후 검증의 전제 조건이 충족되지 않으면 `#require`로 값을 확인해 테스트를 즉시 중단하고 안전하게 언래핑할 수 있다.

- 구체 타입, 오버로드, 하위 타입과 제네릭 가운데 필요한 다형성의 형태를 먼저 선택해야 불필요한 추상화를 피할 수 있다.

- Actor는 재진입할 수 있으므로 `await` 전후에 상태가 같다고 가정하지 말고, 중단점 뒤에서 전제를 다시 확인해야 한다.

- GeometryReader는 부모 배치에 정보를 되돌리기 어렵고 렌더 반복을 유발할 수 있어 단순 좌표 기반 그리기에 제한해 쓰는 편이 안전하다.

- 자동 추적할 수 없는 외부 저장소는 `access`와 `withMutation`으로 접근과 변경 시점을 알려야 한다.

- Linear PCM은 빠르고 동시 재생에 유리하지만 크기가 크고, AAC·MP3 같은 압축 형식은 공간을 줄이는 대신 디코딩 비용과 품질 손실을 고려해야 한다.
- 비트레이트는 파일 크기와 품질의 절충이므로 음성·음악의 특성에 맞춰 실제 결과를 비교해 정해야 한다.
