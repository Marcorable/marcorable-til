# 2026-11-15

## 오늘의 기록

경력기술서의 POS, 첫 구매 혜택, 디자인 시스템과 라우팅 관련 문구 9개를 다듬어 3페이지 PDF 프리뷰로 만들고 레이아웃을 확인했다. 학습 기록으로는 SwiftUI 성능의 변경 지역성부터 ScrollView·Charts·SwiftData, Metal 3·Vision·Translation API까지 최근 Apple 플랫폼의 UI와 데이터 처리 흐름을 폭넓게 정리했다.

## 작업 기록

### 완료

- 경력기술서의 POS·첫 구매 혜택·공통 디자인 규격·iOS Foundation/Component·OrthogonalScrollingBehavior·Route/ReStack·디자인 시스템 관련 문구와 순서를 수정했다.
- 수정본을 3페이지 PDF 프리뷰로 만들고 기존 페이지 구성과 간격, 잘림과 부자연스러운 줄바꿈 여부를 확인했다.

### 진행 중

- 문구 수정은 프리뷰에만 반영했으며 마켓컬리 원본 경력기술서와 제출용 병합 PDF 교체는 남아 있다.

### 다음에 할 일

- 프리뷰의 최종 문구를 확인한 뒤 원본 경력기술서와 제출용 병합 PDF에 반영한다.

## 배운 점

### SwiftUI 성능은 변경 범위를 좁히는 문제다

- 무엇이 바뀌었고 어떤 View가 그 값에 의존하며 얼마나 많은 UI 작업이 다시 실행되는지 추적하면 성능 문제를 구조적으로 진단할 수 있다.
- `body` 안의 정렬·필터링·포맷팅은 render model로 옮기고, stable identity와 좁은 binding으로 불필요한 재계산과 갱신을 줄인다.
- 비동기 작업은 `body`에서 직접 만들지 않고 `.task`나 `.task(id:)`로 View lifecycle과 연결해 취소와 오래된 결과 반영을 제어한다.

### 최신 Apple 프레임워크는 선언적 구성과 기기 내 처리를 확장한다

- ScrollView의 target, position, transition API와 Swift Charts의 mark 조합은 화면 구성과 상호작용을 선언적으로 표현한다.
- SwiftData는 `@Model`, ModelContainer·ModelContext, `#Predicate`와 `@Query`로 모델 정의부터 조회와 UI 갱신까지 연결한다.
- Metal 3의 렌더링 기능, Vision의 이미지 분석과 Translation의 온디바이스 모델은 기기 역량과 지원 상태를 먼저 확인하는 설계가 필요하다.

## 기록에서 배운 점

### [The SwiftUI Performance Skill](https://livsycode.com/swiftui/the-swiftui-performance-skill/)

- 성능 진단은 identity, `body` 비용, 넓은 상태 의존성과 async lifecycle 순서로 변경 지역성을 확인하는 방식이 효과적이다.
- 목록은 안정적인 ID를 사용하고 정렬·필터링·포맷팅은 렌더링 경로 밖으로 옮겨야 한다. `.id(UUID())`나 index 기반 ID는 재사용과 diffing을 방해한다.
- `.task(id:)`는 입력 변화에 따라 이전 작업을 취소할 수 있지만, 취소를 무시한 오래된 결과가 현재 UI를 덮지 않도록 결과 적용 시점도 관리해야 한다.

### [Discover Metal 3](https://app.notion.com/p/40cd5c4871bd81a1afdbe3549adfb291)

- Metal 3는 빠른 리소스 로딩, 오프라인 컴파일과 MetalFX 업스케일링으로 로딩과 렌더링 비용을 줄인다.
- Mesh shader, 개선된 ray tracing과 머신러닝 가속을 제공하며 사용 전 `device.supportsFamily(.metal3)`로 지원 여부를 확인해야 한다.

### [Beyond scroll views](https://app.notion.com/p/40cd5c4871bd81a4904fca1084497d17)

- `.safeAreaPadding`과 `.contentMargins`는 스크롤 콘텐츠와 표시 영역의 여백을 구분해 다룬다.
- `.scrollTargetBehavior`, `.scrollTargetLayout`과 `.containerRelativeFrame`을 조합하면 paging과 view-aligned scrolling을 선언적으로 구성할 수 있다.
- `.scrollPosition`과 `.scrollTransition`은 위치 제어와 스크롤에 따른 시각 변화를 View 상태에 연결한다.

### [Hello Swift Charts](https://app.notion.com/p/40cd5c4871bd81a9bd1ee8980f675150)

- `BarMark`, `PointMark`, `LineMark`를 데이터와 함께 조합하고 style과 symbol을 적용해 다양한 차트를 SwiftUI 문법으로 표현한다.
- 다크 모드, 화면 크기, Dynamic Type, VoiceOver·오디오 그래프, 대비와 지역화를 함께 고려해야 데이터의 의미가 환경에 따라 사라지지 않는다.

### [What's new in Vision](https://app.notion.com/p/40cd5c4871bd81ceb224ed6f56cf76db)

- Vision은 사람 분할, 손 자세, 궤적, 텍스트·바코드 인식과 optical flow를 공통 요청 모델로 제공한다.
- 텍스트 인식의 자동 언어 감지와 optical flow의 해상도별 revision처럼 요청별 최신 기능과 비용을 비교해 선택해야 한다.
- Quick Look debugger preview를 사용하면 분석 결과를 개발 중 시각적으로 확인할 수 있다.

### [Meet the Translation API](https://app.notion.com/p/40cd5c4871bd81d6bdd3fd1dcebd1656)

- Translation API는 공유 언어 자산과 다운로드·권한·백그라운드 처리를 프레임워크가 관리하는 온디바이스 번역을 제공한다.
- batch translation은 `clientIdentifier`로 입력과 결과의 대응 관계를 유지하고, 번역 전에 language pairing status를 확인할 수 있다.
- 요청 하나는 하나의 언어 쌍을 다루며 시뮬레이터에서 동작하지 않으므로 실제 기기 검증이 필요하다.

### [What’s new in SwiftUI (WWDC22)](https://app.notion.com/p/40cd5c4871bd81e89f7ad86c1b2d27e1)

- NavigationStack·NavigationSplitView와 window API는 화면 이동과 멀티윈도우 구성을 명시적인 상태로 표현한다.
- PhotosPicker, ShareLink, Transferable과 `dropDestination`은 시스템 데이터 교환 흐름을 SwiftUI 안에서 연결한다.
- Grid와 확장된 controls·tables·searchable API로 적응형 화면 구성을 더 일관된 방식으로 만들 수 있다.

### [Meet SwiftData](https://app.notion.com/p/40cd5c4871bd81fdba55e870d0c06d45)

- `@Model`과 `@Attribute`, `@Relationship`, `@Transient`로 저장 모델과 관계, 비저장 속성을 선언한다.
- ModelContainer가 저장 구성을, ModelContext가 변경과 조회를 담당하며 `#Predicate`, FetchDescriptor와 SortDescriptor로 질의를 만든다.
- SwiftUI에서는 `.modelContainer`와 environment modelContext를 연결하고 `@Query`로 저장소 변화에 맞춰 화면을 갱신한다.
