# 2026-11-09

## 오늘의 기록

ReciteScripts의 화면 상태와 권한 분기 흐름을 Penpot에 정리하고, 텍스트 선택 하이라이트와 I-beam을 이용한 최종 앱 아이콘을 양 플랫폼 에셋으로 만들었다. 정적 분석과 테스트 102개를 통과한 PR #75를 병합하고 관련 Linear 작업도 완료했다.

채용 준비에서는 NH투자증권과 다우기술 지원 문안을 보강하고 쓰리아이, 블록체인랩스, 나인투원의 공고를 실제 경험과 대조했다. CCRecorder는 App Intents·Quick Actions·App Actions·App Shortcuts를 하나의 `녹음 화면 열기` 라우트로 연결하는 방향을 정리했으며, Swift와 iOS 관련 Record 여섯 건을 다시 읽어 핵심 내용을 추렸다.

## 작업 기록

### 완료

- Penpot에 대본 목록·추가·낭독 설정·진행·완료·오류·접근성 화면, 의미 기반 토큰과 권한 분기 Wireflow를 정리했다. 대본 선택 후 마이크 권한을 확인하고 반복 횟수 Bottom Sheet를 거쳐 낭독 화면으로 이동하는 흐름을 확정했다.
- Flat 스타일의 최종 앱 아이콘을 Penpot `v1.0.0`으로 남기고 iOS AppIcon 15개 규격과 Android launcher 5개 density로 생성했다. 알파 채널, `flutter analyze`와 테스트 102개를 검증했다.
- ReciteScripts PR #75를 모든 검사 통과 후 병합하고 Penpot 디자인 링크를 추가했다. Linear MAR-49와 MAR-50도 완료 처리했다.
- NH투자증권 지원용 경력기술서 2,378자와 자기소개서 2,410자를 정리하고 6페이지 포트폴리오의 레이아웃을 검수했다.
- 다우기술 MTS 채널 개발 문안은 경력기술서 1,831자와 자기소개 1,495자로 작성했다. 포트폴리오는 모듈화 → 상품상세 → MVVM → Firebase 순서로 제안했다.
- 쓰리아이, 블록체인랩스 Newnal, 나인투원 쏘카일레클 공고의 요구와 경험 근거를 대조했다. AI Agent 검증·아키텍처·온디바이스 AI·서비스 운영은 강점으로, BLE·GPS·보안과 제품 내부 AI Agent 경험은 보완 영역으로 구분했다.
- CCRecorder의 플랫폼별 시스템 진입 기능을 구분하고, 자동 녹음을 시작하지 않은 채 공통 녹음 화면 라우트로 연결하는 구조를 정리했다.

### 진행 중

- Android 실기기에는 ReciteScripts `develop` 커밋 `dd6776e` 설치를 확인했다. iPhone은 실행됐지만 검증 도중 공유 워크스페이스 브랜치가 바뀌어 같은 SHA의 빌드였는지 추가 확인이 필요하다.
- 채용 문안과 공고 분석은 끝났지만 실제 지원 제출과 신규 포트폴리오 PDF 생성은 진행하지 않았다.
- CCRecorder 시스템 진입 기능은 개념과 공통 라우트만 정리했으며 실제 구현은 시작하지 않았다.

### 다음에 할 일

- ReciteScripts의 같은 기준 커밋을 iPhone에 다시 설치해 양쪽 실기기 검증 조건을 맞춘다.
- 지원할 공고를 선택한 뒤 회사별 최종 문안과 포트폴리오 PDF를 확정한다.
- CCRecorder의 공통 녹음 라우트와 플랫폼별 진입 기능을 구현 작업 단위로 분리한다.

## 배운 점

### 플랫폼 기능의 이름보다 공통 사용자 동작을 먼저 정의한다

- iOS App Intents와 Home Screen Quick Actions, Android App Actions와 App Shortcuts는 호출 지점과 등록 방식이 다르다.
- 각 기능이 독립적인 화면 이동 로직을 가지게 하기보다 `녹음 화면 열기`라는 내부 라우트를 공유하면 권한과 녹음 상태 관리를 기존 UI 흐름에 모을 수 있다.
- 음성 명령이나 바로가기는 화면까지 이동시키고 실제 녹음은 사용자가 시작하게 하면 예기치 않은 자동 실행을 피할 수 있다.

### 지원 문안은 강점과 근거가 없는 영역을 함께 관리해야 한다

- 여러 공고에서 아키텍처, 운영 경험과 AI Agent 검증 체계는 반복해서 활용할 수 있는 강점이었다.
- BLE·GPS·암호화처럼 공고에는 중요하지만 최근 근거가 부족한 항목은 유사 경험으로 부풀리지 않고 보완 영역으로 분리해야 한다.
- 문안의 분량보다 각 경험이 어떤 문제 해결 역량을 보여 주는지 문단 끝에서 명확히 연결하는 편이 설득력을 높인다.

## 기록에서 배운 점

### [Quick](https://github.com/Quick/Quick/tree/main/Documentation/ko-kr)

- 테스트는 Arrange–Act–Assert로 환경, 실행과 검증을 나누고 이름에 조건과 기대 동작을 드러내면 읽기 쉬워진다.
- 내부 DB 크기 같은 구현 세부보다 저장한 값을 다시 불러올 수 있는지처럼 사용자가 기대하는 동작을 검증해야 리팩터링에 덜 취약하다.
- `setUp`과 helper로 공통 준비 코드를 줄이고, Quick의 `describe`·`context`·`it`과 Nimble의 assertion으로 조건과 결과를 서술적으로 표현할 수 있다.

### [SwiftUI 공식 튜토리얼 노트](https://app.notion.com/p/40cd5c4871bd812989f7f829a0626729)

- SwiftUI 앱은 `@main`이 붙은 `App`에서 Scene을 반환하고, 각 View의 `body`가 화면의 콘텐츠와 계층을 선언한다.
- `HStack`, `VStack`, `ZStack`으로 작은 View를 조합하고 modifier가 새 View를 반환하는 흐름을 연결해 화면을 구성한다.
- `@State`는 변경 가능한 값의 source of truth를 제공하고 `$` 바인딩은 하위 View나 MapKit 같은 다른 UI 요소와 상태를 동기화한다.
- Canvas와 Preview의 즉시 피드백을 활용하면 코드, Inspector와 시각 결과를 함께 보며 커스텀 View를 다듬을 수 있다.

### [PinLayout](https://zeddios.tistory.com/1243?category=682196)

- PinLayout은 Auto Layout 제약 없이 View의 위치와 크기를 수동으로 계산해 배치하는 프레임워크다.
- Record 본문에는 프레임워크의 목적만 메모되어 있으며 구체적인 API 사용법이나 Auto Layout과의 비교는 아직 정리되지 않았다.

### [Swinject](https://github.com/Swinject/Swinject)

- 의존성 주입은 객체가 필요한 구현을 직접 만들지 않고 외부에서 공급받게 하며, 결합도를 낮추고 테스트 가능성을 높이는 제어 역전 방식이다.
- Container에는 Service, Component와 Factory를 등록하고 resolve 과정에서 객체 그래프를 조립한다.
- Graph, Transient, Container와 Custom scope는 인스턴스를 같은 resolve 그래프에서만 공유할지, 매번 만들지, 앱 전체에서 유지할지를 결정한다.
- `Assembly`와 `Assembler`를 사용하면 모듈별 등록 책임을 나누면서 하나의 공유 Container에서 의존성을 해결할 수 있다.

### [OAuth 2.0](https://oauth.net/2/refresh-tokens/)

- OAuth 2.0은 인증 자체보다 제한된 자원 접근 권한을 위임하는 인가 표준이다.
- 웹, 데스크톱, 모바일과 거실 장치처럼 클라이언트 환경에 맞는 권한 부여 흐름을 제공하면서 클라이언트 개발의 단순성에 초점을 맞춘다.
- 규격과 확장은 IETF OAuth Working Group에서 개발되며, Refresh Token은 후속 학습 자료로 연결되어 있다.

### [Swift.org](https://app.notion.com/p/40cd5c4871bd81bf932fd161d08fb98c)

- Swift는 사용 전 초기화, 배열 범위와 정수 오버플로 검사, Optional을 통한 `nil` 처리와 타입 안전성을 언어 수준에서 강조한다.
- 값이 바뀌지 않으면 `let`을 사용하고 참조 타입은 ARC 생명주기를 고려해야 한다. Tuple, 패턴 매칭과 타입 추론은 간결한 표현을 돕는다.
- 언어 기능은 Swift 버전과 연결되므로 Opaque Type과 Concurrency처럼 최소 버전이 있는 기능을 사용할 때 빌드 환경의 호환성을 확인해야 한다.
