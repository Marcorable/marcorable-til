# 2026-11-07

## 오늘의 기록

ReciteScripts 추가 버튼의 기본·큰 글자 크기 접근성 검증을 마치고 PR #74를 `develop`에 병합했다. 스토어 에셋 자동화에서는 iOS와 Android의 기본·큰 글씨 화면 16장을 재생성해 규격·중복·민감정보와 양 플랫폼 빌드를 확인했으며, 로컬 구현과 스테이징 이후의 커밋·PR·스토어 업로드는 다음 단계로 남겼다.

워크스페이스의 역할 표시명은 책임을 더 분명히 드러내도록 `QA`에서 `Tester`로 바꾸되 테스트 활동명과 기존 세션 경로는 유지했다. 당근 iOS 공고에 등장한 라이브러리는 서버 데이터 변환, 목록 구성, 셀 레이아웃이라는 서로 다른 계층의 문제를 푼다는 관점으로 정리했다.

## 배운 점

### 접근성은 확대 환경과 기본 환경을 함께 검증해야 한다

- 큰 글자 크기에서 레이아웃을 개선해도 기본 배율의 48×48 터치 영역을 별도로 단언하지 않으면 기본 환경의 회귀를 놓칠 수 있다.
- 접근성 완료 조건은 화면 모양뿐 아니라 터치 영역, 의미 정보, 정적 분석과 양 플랫폼 빌드까지 함께 확인할 때 재현 가능해진다.

### 역할 이름과 활동 이름은 구분할 수 있다

- `Tester`는 독립적으로 테스트하고 재현·보고하는 책임을 드러내고, `QA`는 그 역할이 수행하는 품질 활동명으로 남길 수 있다.
- 표시명을 바꾸더라도 진행 중인 세션을 식별하는 내부 경로까지 즉시 바꾸면 운영 상태가 끊길 수 있으므로 외부 표현과 내부 식별자를 분리해 다뤄야 한다.

### 라이브러리는 데이터 흐름의 계층으로 이해할 수 있다

- `KarrotCodableKit`은 서버 JSON을 Swift 모델로 바꾸고, `KarrotListKit`은 모델을 목록으로 구성하며, `FlexLayout`은 셀 내부의 배치를 담당한다.
- 이름을 개별적으로 외우기보다 데이터 변환 → 목록 구성 → 셀 레이아웃으로 연결하면 각 도구가 해결하는 경계를 더 쉽게 설명할 수 있다.
