## 배운 점

### 값 타입 안의 참조 타입은 자동으로 깊은 복사되지 않는다

- struct는 값 의미론을 갖지만, 저장 프로퍼티가 class 인스턴스를 참조하면 struct를 복사해도 그 참조 대상은 공유된다.
- 독립된 상태가 필요하면 참조 객체를 새로 만드는 깊은 복사나, 변경 시점에 복사하는 Copy-on-Write 구조를 명시적으로 설계해야 한다.
- 기본 선택은 struct로 두되 객체의 정체성, 상속, Objective-C 상호 운용, 공유 상태가 필요할 때 class를 선택하는 기준이 유용하다.

### escaping 여부는 클로저와 캡처의 수명을 바꾼다

- 함수가 반환된 뒤에도 프로퍼티 등에 저장되어 실행되는 클로저 매개변수에는 `@escaping`이 필요하다.
- escaping 클로저가 참조 타입을 강하게 캡처하면 수명이 연장되고 순환 참조가 생길 수 있으므로 `self`와 capture list를 의식적으로 다뤄야 한다.
- `withoutActuallyEscaping`은 non-escaping 클로저를 제한된 동적 범위에서 escaping API에 전달하기 위한 도구다. 그 범위 밖으로 실제 탈출시키면 런타임 오류가 발생할 수 있다.

### 테스트와 비동기 흐름은 정상·실패·종료를 함께 모델링한다

- Swift Testing은 `@Test`, `#expect`, trait, suite, 매개변수화와 병렬 실행을 조합해 테스트의 의도와 실행 조건을 선언적으로 표현한다.
- `AsyncSequence`는 비동기 값의 흐름을 `for await`로 소비하며 정상 종료와 오류 종료를 모두 표현한다. callback이나 delegate 기반 API는 `AsyncStream` 계열로 감쌀 수 있다.
- `Result` 기반 단위 테스트는 success와 failure 양쪽을 검증해야 하며, 값 비교에는 대상 타입의 `Equatable` 조건도 고려해야 한다.

### 아키텍처 경계는 모델과 의존성의 방향을 분명하게 한다

- DDD의 Entity, Value Object, Aggregate, Repository와 Bounded Context는 도메인 모델의 경계와 책임을 나누는 도구다.
- 슈퍼앱처럼 기능이 커질수록 앱 구성, 비즈니스 로직, UI 로직을 분리하고 Composition으로 기능을 조립하는 방식이 확장성에 유리하다.
- REST는 자원 중심 URI와 HTTP method뿐 아니라 self-descriptive message와 HATEOAS 같은 제약까지 포함해 이해해야 한다.

## 기록에서 배운 점

### [Daily iOS / 1주 2일차](https://app.notion.com/p/415d5c4871bd80398db6fd19210a1553)

- struct와 class의 값·참조 의미론, ARC와 Copy-on-Write를 비교하고 각각의 선택 기준을 정리했다.
- 저장되는 closure의 `@escaping`, 캡처 수명과 `withoutActuallyEscaping`의 제한을 확인했다.
- `Any`는 값 타입과 함수까지 담을 수 있고, `AnyObject`는 class 인스턴스만 나타내며, `NSObject`는 Objective-C 루트 클래스 계층의 기반이다.
- delegate protocol을 `AnyObject`로 제한하면 `weak` 참조를 사용할 수 있어 순환 참조를 피할 수 있다.

### [Swift Testing](https://app.notion.com/p/40cd5c4871bd81eaa775ffc8fc2f6917)

- 테스트를 struct와 `@Test`로 선언하고 trait, tag, suite, 매개변수화, known issue와 exit test로 실행 조건과 기대를 표현한다.
- XCTest와 공존하면서 점진적으로 도입할 수 있고, 병렬 실행이 기본이므로 공유 상태가 있는 테스트는 격리 전략이 필요하다.

### [Meet AsyncSequence](https://app.notion.com/p/40cd5c4871bd812eb17fc09f64e57d2c)

- 비동기로 도착하는 값을 하나의 sequence로 모델링하면 파일, URL, Notification 같은 이벤트를 일관된 반복문으로 소비할 수 있다.
- custom sequence를 만들 때 iterator의 상태와 오류 종료, 취소와 동시성 안전성을 함께 고려해야 한다.

### [Image 다루기 in iOS](https://app.notion.com/p/40cd5c4871bd818b9d78c9b3e9e2b1b4)

- Core Image는 `CIImage`, `CIFilter`, `CIContext`를 중심으로 필터 체인을 구성하고 최종 시점에 지연 렌더링한다.
- 반복 처리에서는 context 재사용과 GPU·CPU 선택이 성능과 메모리 사용에 영향을 준다.

### [Audio with AVFoundation](https://app.notion.com/p/40cd5c4871bd81c3ad1ee5ec8be4d624)

- 녹음과 재생뿐 아니라 audio session, 인터럽션, route change와 재생 상태를 함께 관리해야 안정적인 오디오 기능이 된다.
- metering, audio effect와 TTS 같은 확장 기능도 세션 생명주기 안에서 다뤄야 한다.

### [Handling Keyboard & Pointer Interactions in SwiftUI](https://app.notion.com/p/40cd5c4871bd81778c2cc9d4d85e36e5)

- 키보드 safe area, `@FocusState`, toolbar와 dismiss 흐름을 조합해 입력 UI를 구성한다.
- iPad와 Mac 환경까지 고려하면 하드웨어 키보드 단축키와 pointer interaction도 핵심 입력 수단으로 취급해야 한다.

### [DDD, Domain-Driven Design](https://app.notion.com/p/40cd5c4871bd8155a0e7c496c9c96581)

- Entity와 Value Object의 구분, Aggregate의 일관성 경계, Repository의 저장소 추상화가 도메인 모델의 중심을 이룬다.
- Bounded Context로 언어와 모델의 적용 범위를 한정하고, 계층 간 의존성이 도메인을 향하도록 구성한다.

### [RESTful API](https://app.notion.com/p/40cd5c4871bd81a88633c600e1d3773f)

- 자원 중심 URI, HTTP method, JSON 표현, 상태 비저장성을 REST API의 기본 원칙으로 복습했다.
- self-descriptive message와 HATEOAS는 클라이언트가 표현만으로 다음 동작과 의미를 이해하도록 돕는 제약이다.
