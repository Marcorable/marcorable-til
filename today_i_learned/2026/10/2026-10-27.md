# 2026-10-27

## 오늘의 기록

CCRecorder에서는 AppTarget의 화면 코드를 Presentation 레이어로 옮기는 작업을 이어가며, TCA 화면 Store와 상태를 가진 `RecordingUsecase`의 수명 경계를 검토했다. ReciteScripts에서는 이슈 #26의 iOS `SpeechAnalyzer` STT 어댑터 구현과 자동 검증을 진행했으며, 원격 반영과 실기기 검증은 다음 단계로 남겼다.

구조 작업을 뒷받침하기 위해 Swinject 대안과 Clean Architecture 규칙의 배치 원칙을 정리했다. ReturnTheFavor를 활용한 React Native 학습 순서를 세우고, Orca의 세션 근거를 이력서 작성 환경으로 안전하게 전달하는 방법도 구체화했다.

## 작업 기록

### 완료

- Factory, `swift-dependencies`, SafeDI, Needle, Knit을 Swinject와 비교하고, 현재 TCA 구조에서는 `swift-dependencies`를 유지하는 방향이 가장 단순하다고 정리했다.
- Clean Architecture의 의존 방향과 Repository 경계는 룰로, 기존 구조의 점진적 전환 절차는 `migrate-clean-architecture` 스킬로 분리하기로 했다.
- 영속성·동시성·모듈 배치 문서의 책임과 중복, `Presentation`과 `UserInterface` 용어 통일 필요성을 확인했다.
- ReturnTheFavor를 기반으로 JavaScript, TypeScript, React, Expo Router, SQLite를 순차적으로 학습하는 로드맵을 정리했다.
- Orca 세션을 `RN_RESUME_CONTEXT.md`로 정제한 뒤 Claude 네이티브 앱에 전달하는 이력서 작성 흐름을 설계했다.

### 진행 중

- CCRecorder의 AppTarget 화면 코드를 Presentation 레이어로 옮기고, 화면 Store와 `RecordingUsecase`의 수명 및 `prepare` 취소 경합을 검토하고 있다.
- ReciteScripts 이슈 #26에서 iOS `SpeechAnalyzer` STT 어댑터 구현과 자동 검증을 진행하고 있다.

### 다음에 할 일

- CCRecorder의 녹음 의존성 수명 경계를 확정하고 취소 경합 회귀 테스트를 보강한다.
- ReciteScripts 이슈 #26 브랜치를 push하고 PR을 만든 뒤 CodeRabbit 리뷰를 요청한다.
- iOS 26 이상 실기기에서 STT 동작을 검증하고 자동 검증 결과와 분리해 기록한다.
- `marcorable-kit`의 Clean Architecture 문서를 책임별 룰과 마이그레이션 스킬로 실제 정리한다.
- ReturnTheFavor의 검증된 구현·학습 근거를 모아 `RN_RESUME_CONTEXT.md` 초안을 작성한다.

## 배운 점

### 의존성 도구보다 수명 경계를 먼저 정해야 한다

- TCA Feature가 `@Dependency`를 사용하는 상황에서 다른 DI 컨테이너를 추가하면 주입 방식과 수명 규칙이 이중화될 수 있다.
- 녹음처럼 상태를 가진 의존성은 등록 문법보다 어느 Store가 언제 만들고 해제하는지를 먼저 명확히 해야 한다.
- 컴파일 타임 안전성이 필요한지, 런타임 교체와 테스트 편의가 중요한지를 구분해야 라이브러리 선택 기준이 선명해진다.

### 원칙과 전환 절차는 다른 문서가 필요하다

- 의존 방향, Domain Entity, Repository 경계처럼 항상 적용되는 판단 기준은 짧은 룰에 적합하다.
- 기존 저장 구조 조사, Aggregate 선정, 소비 경로 전환, 회귀 검증처럼 순서가 중요한 작업은 실행형 스킬로 분리하는 편이 재사용하기 쉽다.
- 영속성 구현과 동시성 경계를 별도 문서로 나누면 Clean Architecture의 핵심 원칙이 SwiftData 같은 특정 기술에 묻히지 않는다.
