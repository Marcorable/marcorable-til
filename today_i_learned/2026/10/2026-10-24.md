# 2026-10-24

## 오늘의 기록

CCRecorder에서는 노트 목록 화면을 TCA 구조로 옮겼다. 화면 상태와 삭제 의도를 Feature가 소유하도록 바꾸고, 재사용 목록 View와 화면 진입점의 이름을 정리하면서 sheet presentation을 TCA 바인딩 흐름에 연결했다.

ReciteScripts에서는 MVP 요구사항 리뷰를 반영한 뒤 Flutter PRD와 요구사항 추적표를 완성했다. 이어서 실제 라우트를 목록·대본 추가·낭독 세 개로 제한하고, 오류와 이탈 상황까지 포함한 핵심 사용자 흐름을 문서화했다.

## 작업 기록

### 완료

- CCRecorder의 노트 목록을 `NoteListScreen.Root.Feature` 중심의 TCA 구조로 전환했다.
- 노트 선택과 삭제 상태를 Feature로 옮기고 삭제 동작을 `DeleteNoteUsecase` 의존성으로 분리했다.
- 재사용 목록 View를 `NoteBoard`로 정리하고 `BindableAction`·`BindingReducer`를 통해 sheet 상태를 연결했다.
- CCRecorder Feature 테스트 3개와 `git diff --check`를 통과했다.
- ReciteScripts PR #55의 리뷰 7건을 반영해 STT 중단, 늦은 결과 폐기, 플랫폼 이벤트 정규화와 Android 검증 기준을 보완했다.
- 리뷰 반영 커밋을 push하고 모든 리뷰 스레드를 해결한 뒤 PR #55 병합 상태를 확인했다.
- Flutter MVP PRD와 요구사항 추적표를 작성한 PR #56을 생성하고, 병합 후 작업 공간을 정리했다.
- MVP 화면을 목록·대본 추가·낭독 세 개의 라우트로 제한하고 오류·이탈 흐름을 정의한 PR #57을 생성했다.

### 진행 중

- CCRecorder에서 SwiftData `Note`를 presentation 상태로 직접 보관할 때 발생하는 Sendable 경고의 안전한 해소 방식을 검토하고 있다.
- ReciteScripts PR #57은 Codex·CodeRabbit 리뷰를 기다리고 있다.

### 다음에 할 일

- CCRecorder의 presentation 상태를 명시적 dismiss Action 또는 `persistentModelID` 기반으로 바꿀지 결정하고 변경 사항을 커밋한다.
- ReciteScripts PR #57 리뷰에서 유효한 피드백을 반영하고 핵심 사용자 흐름 문서를 확정한다.
- Android STT 스파이크 결과가 준비되면 PRD의 출시 수용 기준을 구체적인 검증 결과로 갱신한다.
