# 2026-10-20

## 오늘의 기록

`marcorable-mvvm`의 UIKit·SwiftUI 예제에서 화면 전환 방식을 `Navigator<Screen>` 중심으로 통일했다. 환경 주입 누락과 삭제된 API 참조를 정리하고, Combine 구독에서 발생할 수 있는 참조 순환도 수정했다. 모든 예제와 패키지의 빌드·테스트를 확인한 뒤 PR #15를 병합하고 `v0.2.0`을 정식 배포했다.

CCRecorder에서는 같은 네비게이션 구조를 적용하는 이슈 #77과 PR #78을 연결했다. `marcorable-kit`에서는 공통 문서 재주입과 YAML 이스케이프를 보완하고 PR #2의 리뷰 스레드를 정리했다.

## 기록에서 배운 점

### 화면 전환 명령과 렌더링 책임 분리

`Navigator<Screen>`은 화면 이동 명령을 발행하고, SwiftUI의 `NavigationStack`과 UIKit의 `UINavigationController`가 각자 명령을 렌더링하도록 나누면 두 UI 체계가 같은 API를 사용할 수 있다. 다만 환경 객체 주입과 구독 생명주기를 빠뜨리면 컴파일 오류나 런타임 오류, 참조 순환으로 이어질 수 있으므로 소유 관계를 함께 검증해야 한다.

### 추상화는 중복보다 의도를 먼저 봐야 한다

중복 제거를 위해 만든 공통 바인딩 타입이 예제의 실제 동작 흐름을 가리면 학습성과 유지보수성이 떨어질 수 있다. 이번에는 공통 `UIKitNavigationBinding`을 제거하고 각 `SceneDelegate`에 네비게이션 처리를 명시적으로 두는 편이 구조를 이해하기 쉬웠다.

### 자동 생성 설정의 안정성

에이전트 설정을 반복 주입하려면 결과가 항상 같아야 한다. 파일 끝의 빈 줄과 YAML 문자열 이스케이프처럼 작은 차이도 재실행 시 불필요한 변경이나 파싱 오류를 만들 수 있으므로 실제 설치 시나리오를 반복 검증하는 과정이 필요하다.
