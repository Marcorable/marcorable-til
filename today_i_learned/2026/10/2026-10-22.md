# 2026-10-22

## 오늘의 기록

CCRecorder의 화면 구조와 MVVM 패턴을 정리한 PR #91을 병합하고, 다음 단계로 RecordScreen의 녹음 상태와 비동기 Effect를 TCA Feature로 옮겼다. Usecase 의존성과 저장 정책을 분리하고 TestStore 검증을 추가했지만, 권한 대기 중 화면 종료와 `prepare`가 경합하는 생명주기 문제를 발견해 후속 수정과 회귀 테스트를 진행하고 있다.

`marcorable-kit`에서는 SwiftUI 공통 규칙과 `marcorable-mvvm` 전용 규칙을 분리하고, CCRecorder에서 검증한 패턴을 바탕으로 `marcorable-tca` 팩과 `Screen.Root` 네이밍을 추가했다. 동시에 `marcorable-workspace`를 만들어 개인 작업의 우선순위, WIP 제한, 승인 경계와 에이전트 자율 운영 흐름을 문서화했다.

## 작업 기록

### 완료

- CCRecorder의 화면 구조 및 MVVM 패턴 정리 PR #91을 `develop`에 병합했다.
- RecordScreen의 녹음 상태와 비동기 Effect를 TCA Feature로 통합하고, Record·SaveConversation Usecase 의존성을 분리했다.
- 취소 생명주기와 저장 정책을 TestStore로 검증하는 테스트를 추가해 커밋 `7e2878e`로 남겼다.
- `marcorable-kit` PR #3을 병합하고 SwiftUI 공통 규칙과 `marcorable-mvvm` 전용 규칙을 분리했다.
- `marcorable-tca` 팩과 `Screen.Root` 네이밍 규칙을 추가하고 Claude·Codex 재주입 및 스킬 검증을 통과했다.
- `marcorable-workspace`에 운영 헌장, 자율 작업 권한, 공통 에이전트 진입점과 자율 운영 루프를 정리했다.
- ReturnTheFavor의 Linear 이슈 MAR-5를 시작하고, 사람별로 주고받은 기록과 보답 약속을 관리한다는 제품 가설을 구체화했다.
- Notion Daily Log 생성 스킬을 실제 템플릿과 공유 뷰 필터로 검증하고, 10월 21일 TIL을 커밋했다.

### 진행 중

- CCRecorder에서 마이크 권한 대기 중 화면을 닫을 때 `prepare`가 뒤늦게 파일을 만들 수 있는 취소 경합을 수정하고 회귀 테스트를 진행하고 있다.
- `marcorable-kit`의 TCA 문서를 실제 CCRecorder 구현과 공식 API에 대조하며 Preview dependency와 초기화 예제의 정확성을 보완하고 있다.
- ReturnTheFavor에서 날짜가 있는 알림과 날짜 없는 보답 목록, 받음·줌 기록 범위를 더 탐색하고 있다.

### 다음에 할 일

- RecordScreen의 `prepare` 취소 경합 수정과 전체 테스트를 마친 뒤 독립 재검토하고 PR 범위를 확정한다.
- `marcorable-tca` 문서 검증을 마치고 CCRecorder에 최신 팩을 동기화한다.
- ReturnTheFavor의 대표 사례를 추가로 확인한 뒤 MAR-5에 첫 문제 정의 결과를 기록한다.
- Swift·iOS 통합 로드맵의 1주차 주제인 타입 시스템, 상태 소유권과 Concurrency부터 최소 재현 실습을 시작한다.
