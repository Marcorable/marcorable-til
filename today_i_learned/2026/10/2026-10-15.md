## 기록에서 배운 점

### [iOS vs React Native — What I Learned After Building the Same App Twice](https://medium.com/@swatimishra2824/ios-vs-react-native-what-i-learned-after-building-the-same-app-twice-ca584a53554e)

- Swift는 앱 시작, 복잡한 애니메이션, 대형 리스트와 네이티브 디자인 일관성에서 높은 통제력을 제공한다.
- React Native는 단순한 화면의 성능 차이가 작으면서 iOS·Android UI 코드의 상당 부분을 공유할 수 있어 빠른 제품 검증에 유리하다.
- React Native는 시작하기 쉽지만 상태 관리, 외부 라이브러리, 네이티브 브리지까지 이해해야 해 숙련 난도가 높아진다. Swift는 진입 장벽이 높지만 강한 타입과 플랫폼 규칙 덕분에 장기적으로 예측하기 쉽다.
- 기술 자체보다 제품의 성능 요구, 출시 속도, 지원 플랫폼과 팀의 기술 역량이 선택 기준이 되어야 한다.

### [if(kakao)26](https://app.notion.com/p/3f8d5c4871bd807ba321f160b9641575)

- 사용자 피드백이 학습 데이터로 이어지는 과정과 `Klone` 사례를 기록했다.
- 현재 Record 본문은 세션 제목과 키워드 수준이므로, 구체적인 데이터 수집·정제·평가 흐름은 추가 정리가 필요하다.

### [10분 만에 Jev 이해하기](https://yozm.wishket.com/magazine/detail/3989/)

- Jev는 긴 응답을 생성하기보다 주어진 상황을 빠르게 분류하고 0 또는 1에 가까운 판단을 반환하는 모델이다.
- 약 70~500ms의 짧은 판단을 내부 루프의 라우팅과 결과 유효성 검사에 활용할 수 있다.
- 모든 판단을 큰 추론 모델에 맡기기보다 저렴하고 빠른 판단 계층을 추가하면 비용과 지연 시간을 줄일 수 있다.
