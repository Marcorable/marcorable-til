# 2026-10-28

## 오늘의 기록

CCRecorder에서는 Presentation 화면 구조와 이벤트 처리를 다듬고, Setting과 RootStack을 Presentation 레이어로 옮겼다. 대체가 끝난 AppTarget의 레거시 구현·의존성·중복 에셋을 제거하고 빌드와 테스트로 구조 전환을 검증했다.

TCA 화면의 의존성 수명과 내비게이션 구성도 함께 정리했다. ReciteScripts에서는 iOS 26 이상 `SpeechAnalyzer` STT 어댑터의 코드 리뷰를 반영해 PR #66을 병합했으며, 실제 한국어 전사 품질은 실기기에서 추가로 확인하기로 했다.

## 작업 기록

### 완료

- CCRecorder의 Presentation 화면 구조와 이벤트 처리를 개선했다.
- Setting 및 RootStack 화면을 Presentation 레이어로 이전했다.
- AppTarget에서 대체 완료된 레거시 구현과 의존성, 중복 에셋을 제거하고 #96 관련 변경을 6개 커밋으로 나눠 기록했다.
- Presentation 및 앱 시뮬레이터 빌드, Domain 테스트와 `git diff --check`를 통과했다.
- Feature는 `@Dependency`로 의존성을 사용하고 Store 생성 시 `withDependencies`로 live 값을 주입하는 화면 단위 수명 모델을 정리했다.
- ReciteScripts 이슈 #26의 iOS `SpeechAnalyzer` 어댑터에 코드 리뷰 수정 5건을 반영하고 PR #66을 병합했다.

### 진행 중

- CCRecorder와 `marcorable-kit`에서 고정 폴더 트리와 파일 배치 강제를 제거하고, 화면 소유권과 책임 중심으로 규칙을 정리하고 있다.
- 독립 세션 화면은 별도 Store로 관리하고 부모에는 종료 이벤트만 전달하는 하이브리드 내비게이션 구성을 검토하고 있다.

### 다음에 할 일

- `marcorable-kit`의 구조 규칙 변경을 검토하고 커밋한다.
- CCRecorder의 남은 화면과 의존성을 Presentation 경계에 맞게 정리한다.
- iOS 26 이상 실기기에서 SpeechAnalyzer의 한국어 전사 동작과 세션 생명주기를 확인한다.

## 배운 점

### 화면 Store가 의존성 수명의 기준이 될 수 있다

- TCA Feature는 `@Dependency`로 의존성을 소비하고 Store를 만들 때 `withDependencies`로 실행 환경의 live 값을 주입할 수 있다.
- 상태를 가진 의존성은 앱 전체 싱글턴보다 해당 화면 Store의 생성·해제 시점에 맞추면 소유권과 정리 책임이 명확해진다.
- 모든 화면을 하나의 Root Store에 넣을 필요는 없다. 독립적인 작업 세션은 별도 Store로 두고 완료나 취소 같은 이벤트만 부모에 전달할 수 있다.

### 구조 규칙은 위치보다 책임을 설명해야 한다

- 고정된 폴더 트리는 프로젝트 규모와 기존 모듈 경계가 달라지면 불필요한 제약이 될 수 있다.
- 화면과 하위 View의 소유권, Domain과 Data의 의존 방향처럼 오래 유지되는 판단 기준을 규칙의 중심에 두는 편이 재사용하기 쉽다.
