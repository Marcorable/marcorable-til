# 2026-W42 · 10월 12일 ~ 18일

> 이 요약은 해당 주간에 작성된 10월 13일~16일 일일 TIL을 기준으로 한다.

## 이번 주 한 줄

지식 관리 구조를 재정비하는 동시에 CCRecorder의 출시 위험을 실제 검증과 hotfix로 해소하고, 이후 개발·학습·커리어 작업의 우선순위를 다시 세웠다.

## 완료한 일

### 지식 관리와 작업 환경

- `marcorable-til`을 `today_i_learned/YYYY/MM` 구조로 정리하고, 책 예제 저장소를 `book/`으로 통합했다.
- `marcorable-wiki`의 Archive와 Obsidian 그래프 구조를 정비해 과거 기록을 더 쉽게 탐색할 수 있게 했다.
- `marcorable-kit`과 `marcorable-orca`의 작업 규칙·자동화 흐름을 다듬었다.

### CCRecorder 릴리스

- App Store 검증 오류 `90474: Invalid bundle`의 원인이 iPad 방향 설정 누락임을 확인했다.
- `hotfix/#69`에서 설정을 수정하고 Release 빌드와 Store Validation을 통과시킨 뒤 PR #70을 `release`에 병합했다.
- App Store Connect 제출 전 개인정보 항목·개인정보처리방침 URL을 확인했고, 연령 등급 설문과 iPad 스크린샷을 추가 점검 항목으로 남겼다.

### 제품·커리어 정리

- ReciteScripts와 ReturnTheFavor의 백로그를 점검해 다음 단계의 우선순위를 정리했다.
- QMarket 두 저장소에서 `QoQ` 관련 커밋 이력을 조사했으나 유의미한 결과는 없었다.
- NHN ACE iOS 개발자 채용에 지원하고 포트폴리오에 AdMob·Firebase 경험을 보완했다.

## 학습과 판단

### SwiftUI 아키텍처

- MVVM은 UI와 프레젠테이션 로직을 분리하는 출발점이며, 대규모 앱에는 기능 경계·데이터 접근 경계·의존성 관리가 추가로 필요하다.
- View / ViewModel / Use Case / Repository의 책임을 분리하고, Router·Coordinator 같은 구조는 실제 복잡성이 생길 때 도입하는 것이 적절하다.

### AI와 플랫폼 선택

- Jev처럼 빠른 판단 모델은 큰 생성 모델을 대체하기보다, 내부 라우팅과 결과 검증을 보완하는 계층으로 활용할 수 있다.
- Swift와 React Native의 선택은 기술 선호보다 성능 요구, 출시 속도, 지원 플랫폼, 팀의 역량을 기준으로 판단해야 한다.

## 다음 주 우선순위

1. CCRecorder의 App Store Connect 제출 정보, 연령 등급, iPad 스크린샷, 릴리스 노트를 최종 검토하고 심사를 제출한다.
2. ReciteScripts의 0단계 회고를 마치고 STT 스파이크를 시작한다.
3. ReturnTheFavor의 MVP 범위와 데이터 삭제 정책을 확정한 뒤 개발 이슈를 분해한다.
4. `marcorable-mvvm`의 검색 Effect 경쟁 상태와 상세 화면 route 재진입 문제를 해결한다.
