# 2026-W45 · 11월 2일 ~ 8일

> 이 요약은 해당 주간에 작성된 11월 2일~7일 일일 TIL을 기준으로 한다. 11월 8일 일일 기록은 아직 없다.

## 이번 주 한 줄

레거시 지식을 추적 가능한 최신 구조로 옮기고, CCRecorder와 ReciteScripts의 구현·검증·출시 흐름을 진전시키는 동시에 반복되는 판단을 에이전트 규칙과 기계적 검증으로 바꾸는 기반을 마련했다.

## 완료한 일

### 지식 구조 마이그레이션

- 레거시 600건의 마이그레이션 목록을 만들고 Record 332건, Todo 38건과 과거 Daily Log 40건을 최신 구조로 이전했다.
- 40일치 TIL을 주제별 Record 72건으로 분리하고 원래 날짜의 Daily Log에서 다시 찾을 수 있도록 연결했다.

## 학습과 판단

### 완료 기준은 계층적으로 기록해야 한다

- 구현 완료, 자동 테스트, 시뮬레이터 빌드, PR 병합과 실제 출시 가능 상태는 같은 의미가 아니다.
- 음성 입력, 접근성, 백그라운드·잠금 화면, 오디오 장치 분리와 마이그레이션은 실제 기기와 운영 환경에서만 확인되는 실패가 있다.
- `Conditional Go`처럼 통과한 조건과 차단 조건을 함께 기록하면 병합된 코드를 곧바로 출시 가능한 산출물로 오해하지 않게 된다.
- 접근성도 큰 글자 화면만 보는 것으로 끝내지 않고 기본 배율의 터치 영역을 함께 단언해야 환경별 회귀를 막을 수 있다.

### 기능 분리는 상태 소유권과 생명주기를 함께 다뤄야 한다

- TCA Child Feature 분리는 타입을 옮기는 작업이 아니라 입력 상태, 내부 Effect, 취소 시점과 완료 신호의 소유권을 정하는 일이다.
- Android 오디오도 Controller가 상태 전이, Backend가 플랫폼 실행, ForegroundService가 운영체제 생명주기를 맡도록 나누면 테스트와 장애 범위가 선명해진다.
- 데이터 저장 성공뿐 아니라 다른 화면으로 돌아왔을 때의 재조회와 표시까지 하나의 사용자 흐름으로 검증해야 한다.

### 재사용 가능한 규칙은 정본과 적용 증거가 모두 필요하다

- 공통 규칙은 `marcorable-kit` 같은 정본에서 관리하고, 앱 저장소에는 사용한 팩·버전·예외와 실제 테스트 결과를 남기는 편이 유지보수하기 쉽다.
- Parent→Child와 Child→Parent처럼 서로 독립적으로 필요한 행동은 작은 원자 스킬로 나누고, 양방향 흐름이 필요할 때 얇은 workflow로 조합한다.
- 문서로 행동을 안내하는 Guide만 늘리지 말고 Hook·테스트·리뷰 같은 Sensor로 결과를 관측해야 같은 실수를 반복하지 않는다.
- 역할의 표시명은 `Tester`처럼 책임을, `QA`는 활동을 나타내도록 구분하되 세션 경로 같은 내부 식별자는 운영 연속성을 고려해 변경한다.

### 지식은 시간과 주제의 두 축으로 연결해야 한다

- Daily Log는 그날의 맥락과 진행 순서를, Record는 다시 꺼내 쓰기 좋은 주제 단위를 보존한다.
- 제목만 복사하지 않고 본문에서 핵심 판단과 적용 조건을 추려야 마이그레이션된 기록이 실제 지식으로 남는다.
- 원본과 대상의 매핑, 복구 가능한 원본 정리와 회사 자료 제외 기준은 대규모 이전의 정확성을 나중에도 검증할 수 있게 한다.

### 이번 주 Record에서 남길 기술 관점

- 적응형 UI는 기기 이름보다 size class, Dynamic Type, 현지화와 창 크기 같은 실제 환경 능력에 대응해야 한다.
- SwiftUI 상태 래퍼와 MVVM 경계, TCA Feature, SOLID는 이름보다 상태와 변경 책임이 어디에 있는지를 설명하는 도구로 사용해야 한다.
- Core Image의 렌더링 레시피, AVAudioEngine의 노드 그래프, Combine의 Publisher 흐름처럼 플랫폼 기능도 데이터와 실행 파이프라인으로 이해하면 조합과 테스트가 쉬워진다.
- TDD의 Red–Green–Refactor, Core Data의 in-memory store와 Swift Testing의 구체적 오류 검증은 변경 후에도 행동을 보존하는 Sensor가 된다.
- Agent Harness는 Model에 프롬프트, 도구, 컨텍스트 정책, Hook, 샌드박스와 피드백 루프를 더한 실행 환경이며, 실패를 규칙으로 바꾸는 ratchet이 품질을 누적시킨다.
