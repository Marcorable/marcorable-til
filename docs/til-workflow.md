# TIL 발행 워크플로

## 목적

Notion은 일상 기록의 원본입니다. 이 레포에는 편집된 Markdown 기록을
남기며, Obsidian vault로도 바로 열 수 있게 유지합니다.

## 원본 선택

Asia/Seoul 시간대를 기준으로 요청한 날짜에 다음 자료를 수집합니다.

1. `Calendar`에서 `날짜`가 해당 날짜이고 `선택`이 `Log`인 항목을 찾습니다.
   `Memo` 영역에 의미 있는 내용이 있어야 합니다. Memo가 비어 있으면 그 날짜의
   TIL 파일은 만들지 않습니다.
2. `Todo`에서 `날짜`가 해당 날짜인 항목을 포함하고, 완료 상태를 보존합니다.
3. `Record`에서 `Date`가 해당 날짜인 항목을 포함하고, `Select`(기록 형식)와
   `Category`(주제)를 함께 보존합니다.

`Calendar`의 `선택`이 `Recruitment`인 항목은 명시적으로 요청하지 않는 한
제외합니다. 비공개이거나 공개에 적합하지 않은 내용도 같은 기준으로 제외합니다.

Daily Log에 삽입된 뷰에는 날짜가 비어 있는 항목도 나타납니다. 이 항목은 아직
날짜가 확정되지 않은 초안 또는 대기 목록으로 취급합니다. 작성자가 항목의 날짜를
당일로 지정한 뒤에만 해당 날짜의 TIL에 포함합니다. 날짜 없는 항목은 여러 날짜에
반복되는 일을 막기 위해 제외합니다.

## 출력 형식

새 일일 파일은 다음 경로에 만듭니다.

```text
YYYY/YYYY.MM/YYYY-MM-DD.md
```

[`templates/daily-til.md`](../templates/daily-til.md)를 출발점으로 사용합니다.
Notion 원문을 그대로 내보내지 않고, 사람이 읽기 좋은 기록으로 정리합니다.

## 메타데이터

모든 생성 TIL에는 YAML frontmatter를 넣습니다.

- `date`: `YYYY-MM-DD` 형식의 발행 날짜
- `source`: 원본으로 사용한 Notion URL
- `tags`: 주로 `Record.Category`에서 정규화한 주제 태그
- `record_types`: `Record.Select`에서 정규화한 기록 형식. 예: `book`,
  `documentation`, `video`
- `status`: 검토 전에는 `draft`, 공유 가능한 상태가 되면 `published`

## 실행과 갱신 규칙

기본은 수동 요청입니다. 예를 들어 “오늘 TIL 정리해줘” 또는
“2026-10-13 TIL 초안 만들어줘”라고 요청합니다. 원하는 글의 밀도가 몇 차례
확인된 후에는 정해진 시각에 자동 실행하는 방식을 추가할 수 있습니다.

검토가 끝난 Markdown 파일은 자동으로 덮어쓰지 않습니다. Notion 원본이 바뀌면
수정안을 먼저 제안하거나, 아직 `draft` 상태인 파일만 갱신합니다.

## 아티클 확장

여러 기록이 하나의 오래 남을 질문을 뒷받침하면, 일일 TIL을 길게 늘리지 않고
별도의 아티클 초안을 만듭니다. 아티클은 일일 아카이브와 분리해 두며, 외부
게시 전에 반드시 검토합니다.
